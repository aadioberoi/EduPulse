# EduPulse
## Student Performance Insights & Early-Warning System

EduPulse is a working B.Sc. Data Science prototype that organizes student-performance indicators and estimates which demo profiles may benefit from an early academic-support conversation. It includes a reproducible synthetic-data generator, a baseline Random Forest classifier, an evaluation script and a Streamlit dashboard.

> **Important:** All generated records are synthetic. The target label is created from a transparent composite-risk rule. Metrics show how well the model reproduces that simulated pattern; they are not evidence of accuracy on real students. Never use this prototype to label, penalize, rank or make consequential decisions about real students.

### Application modules
- Overview dashboard with sample size and academic indicators.
- Individual profile check with a model-estimated support-priority probability.
- Model evaluation with accuracy, precision, recall, F1-score, confusion matrix and feature importance.
- About page covering limitations and future improvements.

### Project structure
- \`app.py\` — Streamlit dashboard.
- \`generate_data.py\` — reproducible synthetic dataset generator.
- \`train_model.py\` — trains and evaluates the baseline model.
- \`data/student_performance.csv\` — generated by the data script.
- \`models/metrics.json\` and \`models/feature_importance.csv\` — evaluation outputs.
- \`models/edupulse_model.joblib\` — generated locally by model training and excluded from Git.
- \`docs/project_report.md\` — project documentation.
- \`.streamlit/config.toml\` — dashboard theme.

### Run locally
Python 3.10 or later is recommended.

\`\`\`bash
python -m venv .venv
# Windows: .venv\\Scripts\\activate
# macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
python generate_data.py
python train_model.py
streamlit run app.py
\`\`\`

The dashboard opens at \`http://localhost:8501\`. Run data generation and model training before starting Streamlit. The trained model file is created locally by \`train_model.py\` and is intentionally not committed to the repository.

### Methodology
1. Generate 600 reproducible synthetic student profiles.
2. Use attendance, study time, assignment average, previous exam score, missed assignments, sleep and support-session count as input features.
3. Generate the demo target using a composite-risk rule; the top 30% of the risk-score distribution are marked as support-priority profiles.
4. Split records into training and hold-out test sets using a stratified 80:20 split.
5. Train a Random Forest classifier with 250 trees and calculate standard classification metrics.
6. Load the saved model into the Streamlit dashboard.

### Limitations and responsible use
- Simulated data cannot represent the full complexity of real student experiences.
- The model learns a proxy for the rule-generated label, not verified future outcomes.
- A low score or alert does not explain why a student may be struggling.
- A real deployment would require institution-approved and representative data, appropriate consent and notice, data minimization, access controls, fairness evaluation, educator review and a way to correct errors.
- Model output must never be the sole basis for academic, disciplinary or financial decisions.

### Future scope
Validate with an approved dataset and a clearly defined outcome; add longitudinal trends; evaluate calibration, subgroup performance and false-positive/false-negative costs; and pilot a teacher-reviewed referral workflow.
